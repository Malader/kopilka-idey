# Бесплатная защита «Копилки идей»

В этой версии нет Cloudflare, Yandex Cloud, сторонней CAPTCHA, платёжных аккаунтов и новых платных сервисов. Используются существующие GitHub Pages, Google Apps Script, таблица, Drive и Telegram. Превышение квот существующих сервисов может остановить отправку; платное расширение автоматически не подключается.

## Ограничения и проверки

| Мера | Настройка |
| --- | --- |
| Общий лимит новых попыток | 20 за скользящие 60 секунд |
| Вспомогательный лимит браузера | 1 попытка за минуту, 5 за скользящий час |
| Суточный бюджет | 100 новых заявок, 200 МиБ вложений; дата по часовому поясу проекта Apps Script |
| Максимальный запрос | 15 МиБ фактического UTF-8 JSON |
| Вложения | До 5 файлов, до 10 МиБ суммарно |
| Разрешённые форматы | PDF, DOCX, XLSX, PPTX, TXT, CSV, JPG/JPEG, PNG, WEBP, GIF |
| Запрещённые форматы | ZIP, старые DOC/XLS/PPT, исполняемые файлы, HTML, SVG и другие форматы вне списка |

Общий лимит и суточные бюджеты хранятся в Script Properties под ScriptLock. Браузерный лимит использует отдельный UserCache, чтобы не вытеснять квитанции. Проверяются типы, длины, обязательные поля, перечисления, почта, согласие, допустимая схема ссылки, метаданные и фактический размер вложений. Неизвестные поля отклоняются. Поле-ловушка и минимальное время заполнения не возвращают ложный успех.

Пользовательские значения с начальным `=`, `+`, `-`, `@` после удаления пробелов записываются в таблицу как текст. В журнал ошибок попадают только код, время и размер запроса; содержимое заявок, файлов, токенов и стек исключения не записываются.

Сохранённая квитанция проверяется до списания лимитов. Повтор возвращает прежний номер и точное число вложений без новых строк, файлов, писем и сообщений. GET квитанции не расходует лимиты новых попыток. При повторе браузер сначала ищет подтверждение, затем при необходимости отправляет данные с прежним `submissionId`. После отказа поля и файлы остаются в форме.

Бюджет резервируется перед сохранением. Возврат допускается только после подтверждённого отсутствия строки и очистки созданных файлов. Если результат записи или очистки неизвестен, резерв сохраняется.

## Telegram

Свойство `SECURITY_TELEGRAM_ALLOWED_CHAT_IDS` содержит разрешённые chat ID через запятую. Рассылка идёт только активным подписчикам из этого списка. `/start` проверяет разрешение; `/last` дополнительно проверяет активную подписку до чтения заявок. Пустой список закрывает рассылку и просмотр всем чатам. Пользователь согласовал двух существующих подписчиков. Их ID не публикуются в репозитории.

Для изменения списка владелец открывает Apps Script → Настройки проекта → Свойства скрипта. Существующие `TELEGRAM_TOKEN`, `TELEGRAM_OFFSET`, `ATTACHMENTS_FOLDER_ID` сохраняются. Для групп разрешение распространяется на участников группы; для узкого доступа использовать личные чаты.

## Публикация

Сначала публикуется новый фронтенд с `clientId`: старый приёмник совместим с этим дополнительным полем. После подтверждения публикации существующее развертывание Apps Script обновляется новой версией на прежнем URL. Старые открытые формы после обновления backend потребуют перезагрузки страницы.

1 октября 2026 года HTTPS для `kopilkaidei.ru` ещё недоступен: GitHub Pages не разрешает Enforce HTTPS, обычная проверка TLS возвращает несовпадение имени сертификата. Текущий HTTP-доступ к странице сохранён. POST и GET приёмника идут на существующий HTTPS-адрес Google, но HTTP-загрузка самой страницы не защищена от изменения содержимого в сети. При готовности сертификата HTTPS нужно включить отдельно; платный SSL не требуется. В этой публикации DNS и Custom domain не меняются, проверки TLS не отключаются.

Демонстрация `?preview=1` не отправляет данные. Локальная HTML-страница без режима preview не отправляет заявки на рабочий сервис. Идентификаторы формируются через `crypto.randomUUID()` или 128 бит `crypto.getRandomValues()`; слабого случайного fallback нет.

## Практические пределы

Это ограничения приложения, а не защита от DDoS. Публичные вызовы Apps Script до проверок могут расходовать квоты выполнения Google. Архитектура и хранилище в этой версии не переносятся.

Анонимный `clientId` можно подделать, а кэш браузерных ограничений может исчезнуть раньше срока. Общий лимит и суточные бюджеты от него не зависят. CAPTCHA отсутствует, поэтому проверка «человек или бот» не выполняется. Персональный лимит требует подтверждённой учётной записи.

Квитанции хранятся 30 минут в ScriptCache и могут быть вытеснены раньше. Отсутствие квитанции означает неизвестный результат, а не доказанный отказ сохранения; постоянного реестра отправок нет. Проверка расширения и base64 не заменяет антивирус. Одна заявка при текущих настройках может расходовать три получателя письма: суточный бюджет нужно сопоставлять с квотами аккаунта и другими скриптами.

## Проверки

111 локальных тестов проверяют лимиты и их сохранение между вызовами, полночь, отказ инфраструктуры, поля и файлы, формулы, Telegram, очистку после частичной записи, квитанции и сохранение формы. Google, Drive, почта и Telegram заменены заглушками.

```powershell
node --test tests/backend-regression.test.cjs tests/frontend-regression.test.cjs tests/security-backend.test.cjs tests/security-frontend.test.cjs
```

После публикации проверяются файлы страницы, JavaScript, GET квитанции и отказ на некорректный POST без полей заявки. Последняя проверка расходует одну попытку лимита, но не создаёт строк, файлов, писем или сообщений Telegram.
